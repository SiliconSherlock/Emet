# Security review notes

This is written for whoever reviews the site before it goes live. In short:
the site is **static**. GitHub Pages serves files as they are, and nothing
runs on a server. The published files are HTML pages, one CSS file, and
**one short script** (`site/workbench.js`, about 340 lines, many of them
comments) that runs search and filters on the front page. There are no
libraries, no cookies, no analytics, and no third-party resources.

## What gets published

Only the `docs/` folder is published (GitHub Pages, "deploy from branch",
folder `/docs`). It is generated by `build.py` and contains:

| Files | What they are |
|---|---|
| `docs/index.html` | front page (the "workbench"): search, filters, list of claims, reader pane. The only page that loads the script, and the only page with a frame |
| `docs/welcome.html` | what the reader pane shows before a claim is picked |
| `docs/<n>/index.html` | one page per claim (`/1` … `/188`) |
| `docs/<n>/panel.html` | the same claim without the site header, for the reader pane |
| `docs/<0nn>/`, `docs/C-0nn/`, `docs/c-0nn/` | one-line forwarding pages (`<meta http-equiv="refresh">`) so `/042` and `/C-042` reach `/42` |
| `docs/verses/index.html` | index by TaNaKh passage |
| `docs/about/index.html` | about page |
| `docs/404.html` | not-found page |
| `docs/style.css` | the only stylesheet (copy of `site/style.css`) |
| `docs/workbench.js` | the only script (copy of `site/workbench.js`) |
| `docs/.nojekyll` | empty; tells GitHub Pages not to process the files |

There are no images, fonts, or other file types.

## The script

`site/workbench.js` is plain, commented JavaScript with no dependencies. Read
it top to bottom; it:

- reads the claim list already on the front page (each item carries
  `data-n`, `data-search`, `data-cites` and `data-answers` attributes written
  by `build.py`);
- hides the items that do not match the search and the book picklist, and
  highlights matched words by building `<mark>` elements with
  `createElement` and `textContent` (never `innerHTML`, so typed text cannot
  become markup);
- on a wide screen, shows the chosen claim in the reader pane by setting the
  frame's `src` to that claim's own page on this site (`42/panel.html`);
- keeps the search, filters and chosen claim in the address bar (`?q=…`)
  with `history.replaceState`;
- handles three keys: `/` (focus search), up and down arrows (step through
  results).

It makes no network requests and stores nothing. The search boxes on other
pages are plain HTML forms (`method="get"`) that open the front page with
`?q=…`; they submit only to this site.

## The reader pane

The front page has one `<iframe>`, the reader pane:

```html
<iframe id="reader" name="reader" title="Selected claim" src="welcome.html"
  sandbox="allow-same-origin allow-popups allow-popups-to-escape-sandbox allow-top-navigation-by-user-activation">
```

It only ever shows this site's own `panel.html` pages, which contain no
script. The sandbox additionally stops anything in the frame from running
script or submitting forms, and lets it change the main window only when the
reader clicks a link (for example "Open full page"). `frame-src 'self'` in
the policy below stops it from showing any other website.

## Protections in every page

Every HTML page carries this Content Security Policy:

```
default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; frame-src 'self'; base-uri 'none'; form-action 'self'
```

- `script-src 'self'`: only script files from this site may run. Inline
  scripts and scripts from anywhere else are refused by the browser, even if
  one were somehow added.
- `default-src 'none'`: the script cannot make network requests of any kind
  (`fetch`, `XMLHttpRequest`, WebSockets), and nothing else can be loaded.
- `frame-src 'self'`: the reader pane can show only this site's pages.
- `form-action 'self'`: the search boxes can submit only to this site.

Every page also sets `<meta name="referrer" content="no-referrer">`, so
following a link to Chabad.org or Sefaria does not tell those sites which
claim the reader was on. Outbound links go only to `www.chabad.org` and
`www.sefaria.org`; nothing from those sites is loaded or embedded.

## How the pages are made

`build.py` (Python standard library only, no network access) reads the JSON
files in `data/` and writes `docs/`.

- All text from the data files goes through `html.escape()` before it is
  written. A claim containing `<script>` would appear on the page as the
  literal text `<script>`.
- After writing, `check_output()` scans every published file and makes the
  build fail if:
  - any page has a `<script>` tag other than exactly
    `<script src="workbench.js" defer></script>` on the front page;
  - any page has an `<iframe>` other than exactly the reader pane above on
    the front page;
  - `docs/workbench.js` differs from `site/workbench.js`, or there is any
    other `.js` file;
  - the script's code (comments aside) uses any of `innerHTML`, `eval(`,
    `Function(`, `fetch(`, `XMLHttpRequest`, `WebSocket`, `cookie`,
    `localStorage`, `postMessage`, `contentDocument`, `http:`/`https:` and
    similar (see `FORBIDDEN_JS` in `build.py`);
  - any page has an inline event handler (`onclick=` etc.), a `javascript:`
    URL, an `object`/`embed`/`base` tag, a form that submits anywhere but
    this site, an input other than a search box or a filter option, or loads
    a script, frame, stylesheet or media file from another site;
  - any page lacks the Content Security Policy, or there is a file type
    other than HTML, CSS and that one script.

`tools/fetch_texts.py` is a separate helper, run by hand, that downloads
public-domain verse text from `www.sefaria.org` and `bible-api.com` into
`data/texts/`. It is not part of the website and the website never calls
those services. It sends no personal data, only Bible references.

## Checking it yourself

From the repository root:

```bash
python3 build.py
```

rebuilds the site and runs the safety check.

These should all print nothing:

```bash
grep -rilE " on[a-z]+=" docs/
```

```bash
grep -rhoE '(src|href|action)="https?://[^"]*' docs/ | grep -vE 'href="https://www\.(chabad|sefaria)\.org/' | sort -u
```

```bash
find docs -type f ! -name '*.html' ! -name '*.css' ! -name '.nojekyll' ! -path docs/workbench.js
```

```bash
diff site/workbench.js docs/workbench.js
```

These should each print exactly one line, `docs/index.html`:

```bash
grep -ril "<script" docs/
```

```bash
grep -ril "<iframe" docs/
```

This should print the same number as the count of HTML files (every page has the policy):

```bash
grep -rl "Content-Security-Policy" docs/ | wc -l
```

```bash
find docs -name '*.html' | wc -l
```

## Hosting settings

On GitHub: **Settings → Pages → Enforce HTTPS** should be ticked. If the
repository has more than one maintainer, consider protecting the `main` branch
so changes need a review.
