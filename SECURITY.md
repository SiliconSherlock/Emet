# Security review notes

This is written for whoever reviews the site before it goes live. In short:
the published website is static HTML, one CSS file, and **one short script**
(`site/search.js`, about 140 lines including comments) that filters the list
of claims on the front page as you type. There are no libraries, no cookies,
no analytics, no third-party resources, and nothing that runs on a server.

## What gets published

Only the `docs/` folder is published (GitHub Pages, "deploy from branch",
folder `/docs`). It is generated by `build.py` and contains:

| Files | What they are |
|---|---|
| `docs/index.html` | front page: search box and list of claims (the only page that loads the script) |
| `docs/<n>/index.html` | one page per claim (`/1` … `/188`) |
| `docs/<0nn>/`, `docs/C-0nn/`, `docs/c-0nn/` | one-line forwarding pages (`<meta http-equiv="refresh">`) so `/042` and `/C-042` reach `/42` |
| `docs/books/…` | browse by book |
| `docs/verses/index.html` | index by TaNaKh passage |
| `docs/about/index.html` | about page |
| `docs/404.html` | not-found page |
| `docs/style.css` | the only stylesheet (copy of `site/style.css`) |
| `docs/search.js` | the only script (copy of `site/search.js`) |
| `docs/.nojekyll` | empty; tells GitHub Pages not to process the files |

There are no images, fonts, or other file types.

## The script

`site/search.js` is plain, commented JavaScript with no dependencies. Read it
top to bottom; it:

- reads the claim list already on the front page (each item carries a
  `data-search` attribute written by `build.py`);
- hides the items that do not match the words typed, and writes one line of
  status text using `textContent` (never `innerHTML`, so typed text cannot
  become markup);
- keeps the search in the address bar (`?q=…`) with `history.replaceState`;
- if the search is a claim number, opens that claim's page (`42/`).

It makes no network requests and stores nothing. The search boxes on other
pages are plain HTML forms (`method="get"`) that open the front page with
`?q=…`; they submit only to this site.

## Protections in every page

Every HTML page carries this Content Security Policy:

```
default-src 'none'; script-src 'self'; style-src 'self'; img-src 'self'; base-uri 'none'; form-action 'self'
```

- `script-src 'self'`: only script files from this site may run. Inline
  scripts and scripts from anywhere else are refused by the browser, even if
  one were somehow added.
- `default-src 'none'`: the script cannot make network requests of any kind
  (`fetch`, `XMLHttpRequest`, WebSockets), and nothing else can be loaded.
- `form-action 'self'`: the search boxes can submit only to this site.

Every page also sets `<meta name="referrer" content="no-referrer">`, so
following a link to Chabad.org or Sefaria does not tell those sites which
claim the reader was on. Outbound links go only to `www.chabad.org` and
`www.sefaria.org`; nothing from those sites is loaded or embedded.

## How the pages are made

`build.py` (Python standard library only, no network access) reads the JSON
files in `data/` and writes `docs/`.

- All text from the data files goes through `html.escape()` before it is
  written. A claim containing `<script>` would appear on the page as the
  literal text `<script>`.
- After writing, `check_output()` scans every published file and makes the
  build fail if:
  - any page has a `<script>` tag other than exactly
    `<script src="search.js" defer></script>` on the front page;
  - `docs/search.js` differs from `site/search.js`, or there is any other
    `.js` file;
  - the script's code (comments aside) uses any of `innerHTML`, `eval(`,
    `Function(`, `fetch(`, `XMLHttpRequest`, `WebSocket`, `cookie`,
    `localStorage`, `postMessage`, `http:`/`https:` and similar (see
    `FORBIDDEN_JS` in `build.py`);
  - any page has an inline event handler (`onclick=` etc.), a `javascript:`
    URL, an `iframe`/`object`/`embed`/`base` tag, a form that submits
    anywhere but this site, an input other than a search box, or loads a
    script, stylesheet or media file from another site;
  - any page lacks the Content Security Policy, or there is a file type
    other than HTML, CSS and that one script.

`tools/fetch_texts.py` is a separate helper, run by hand, that downloads
public-domain verse text from `www.sefaria.org` and `bible-api.com` into
`data/texts/`. It is not part of the website and the website never calls
those services. It sends no personal data, only Bible references.

## Checking it yourself

From the repository root:

```bash
python3 build.py
```

rebuilds the site and runs the safety check.

These should all print nothing:

```bash
grep -rilE " on[a-z]+=" docs/
```

```bash
grep -rhoE '(src|href|action)="https?://[^"]*' docs/ | grep -vE 'href="https://www\.(chabad|sefaria)\.org/' | sort -u
```

```bash
find docs -type f ! -name '*.html' ! -name '*.css' ! -name '.nojekyll' ! -path docs/search.js
```

```bash
diff site/search.js docs/search.js
```

This should print exactly one line, `docs/index.html`:

```bash
grep -ril "<script" docs/
```

This should print the same number as the count of HTML files (every page has the policy):

```bash
grep -rl "Content-Security-Policy" docs/ | wc -l
```

```bash
find docs -name '*.html' | wc -l
```

## Hosting settings

On GitHub: **Settings → Pages → Enforce HTTPS** should be ticked. If the
repository has more than one maintainer, consider protecting the `main` branch
so changes need a review.
